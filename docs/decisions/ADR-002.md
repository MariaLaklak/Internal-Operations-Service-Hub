# ADR-002: Use Prisma with SQLite for the First Implementation

## Status

Accepted

## Context

The first implementation needs durable relational storage for users, departments, and service requests while remaining small enough for the five-week academy. The first vertical slice must prove that a request survives a backend restart.

## Decision

Use Prisma 6.x as the data access layer and SQLite as the database for the first implementation. The backend owns request validation, the seeded demo employee, creation time, and the initial `Submitted` status.

## Consequences

Prisma provides a readable schema and migrations while SQLite keeps local setup simple and avoids an external service. The database file must be preserved between backend restarts. Authentication and full role authorization remain deferred to a later slice.

## Scope

This decision supports the request-submission endpoints:

- `POST /api/requests`
- `GET /api/requests`

The React client does not send requester ID, creation time, or initial status.

ADR-001 remains unchanged and continues to record the earlier relational-model decision.
